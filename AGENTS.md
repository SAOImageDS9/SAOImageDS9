# Agent notes for building SAOImageDS9 from source

This repo is built from this top-level directory. A full build takes
10+ minutes, so prefer the targeted rebuild commands below whenever
possible instead of rebuilding everything from scratch.

## Rebuilding after code changes

- Changed files under `tksao/` (the C++ canvas-item rendering code:
  frames, colorbar, panner, magnifier, etc.)?

  ```
  make tksaoclean tksao ds9clean ds9
  ```

- Changed files under `ds9/` (the Tcl/Tk UI library and app code)?

  ```
  make ds9clean ds9
  ```

`ds9` links against `tksao`, so a `tksao` change requires relinking
`ds9` afterward — the first command handles both in the right order.
Don't fall back to a full top-level rebuild just because a change
touched C++ code; these targeted clean+build pairs are the normal
workflow here.

**There is no header dependency tracking.** Editing a `.h` does *not*
mark the `.o` files that include it as stale, so a plain `make tksao`
after a header change relinks objects compiled against the old layout.
The symptom is not a build error but a working binary that misbehaves
somewhere unrelated: `strlen` segfaults, or ENVI files intermittently
failing to load after `fitsy/file.h` gained members. That is what the
`clean` in `make tksaoclean tksao ds9clean ds9` is for, and why it is
not optional when a header changed. After touching anything in `fitsy/`,
rebuild `fitsy` first (it also reinstalls its headers into `include/`),
then clean-rebuild `tksao` and `ds9`. Check that the clean really ran:
`find tksao -name '*.o' ! -newer fitsy/file.h` should print nothing.

## Adding source files (autoconf)

Each package's `configure` script is checked in, and its source list
comes from `TEA_ADD_SOURCES` in `configure.ac`. `tksao/configure` was
generated by GNU Autoconf 2.71. The only autoconf on this Mac is 2.73,
in `$HOME/local/bin`, and running it on an unchanged `configure.ac`
rewrites `tksao/configure` wholesale (12,202 -> 5,381 lines). So don't
run autoconf. To add a source file, edit the source list by hand in
both `configure.ac` and the checked-in `configure`.

The package `Makefile` is generated by `configure`, and the top-level
target (e.g. `make tksao`) only reruns `configure` when that `Makefile`
is missing. Run `rm tksao/Makefile` before rebuilding so the new file is
picked up; `make tksaoclean` alone won't do it. Clean *before* removing
the `Makefile`: `make tksaoclean` with no `tksao/Makefile` silently does
nothing, leaving every old object in place (see header dependencies
above).

Rerunning `configure` uses the shared top-level `config.cache`, which
refuses to run if the environment differs from the original build. The
original build here had
`PKG_CONFIG_PATH=/opt/X11/lib/pkgconfig:/opt/X11/share/pkgconfig`, so
export exactly that before `make tksao` rather than deleting the cache.

## Parser/lexer changes (bison/flex)

Several `tksao` subsystems (e.g. `tksao/frame/parser.Y` + `lex.L`) have
generated `.C` files checked in, regenerated via `bison`/`flex` rules in
`tksao/Makefile.in`.

**`make parser` is a dependency-free phony target** — plain
`make tksaoclean tksao` does *not* regenerate anything. After editing a
`.Y`/`.L`, the sequence is:

```
cd tksao && make parser        # or the matching target: ciaoparser, ds9parser, ...
cd .. && make tksaoclean tksao ds9clean ds9
```

Use the narrow per-grammar target, **not** `make parsers`, which
regenerates every grammar in the tree and invites unrelated drift.

Version sensitivity: the checked-in generated files are tied to specific
tool versions — `parser.C` is stamped `made by GNU Bison 2.3` and
`lex.C` `YY_FLEX 2.6.4`. macOS's stock `/usr/bin/bison` (2.3) matches
exactly, so `parser.C`/`.H` regenerate byte-identically. A Homebrew
bison (3.x) on `PATH` would rewrite these files wholesale — keep it off
the `PATH` for this build.

flex does **not** regenerate cleanly, even though every candidate says
2.6.4. `/usr/bin/flex` is a shim for Xcode's toolchain flex, which uses
`size_t`/`ssize_t` where the checked-in `lex.C` files use `int`
(~46 lines of skeleton churn per lexer, seen for both `fitsy/lex.C` and
`tksao/frame/lex.C`). Upstream flex 2.6.4 (conda-forge) differs too.
The checked-in files match neither, probably a distro-patched flex.
Worse, Xcode's flex declares `ssize_t LexerInput()`, which doesn't
compile against the checked-in `FlexLexer.h`. Each package has its own
`FlexLexer.h` shared by all of its lexers, so regenerating one lexer
with Xcode's flex means replacing that package's `FlexLexer.h` with
Xcode's (`xcrun -f flex` → `../include/FlexLexer.h`; keep any local
additions, e.g. `fitsy`'s public `void begin(int,int);`) and
regenerating every other lexer in that package. This was done for
`fitsy` (`lex.C`, `nrrdlex.C`, `envilex.C`).

`fitsy/` (the top-level FITS reader library, home of the filename
bracket grammar `fitsy/parser.Y` + `lex.L`) has its own `Makefile`
with the same narrow targets (`parser`, `nrrdparser`, `enviparser`).
It's a separate library, so after a `fitsy` change rebuild everything
that depends on it:

```
make fitsyclean fitsy tksaoclean tksao ds9clean ds9
```

Before editing any `.Y`/`.L`, sanity-check the toolchain with a no-op
regen: run the target with no source changes and confirm `git diff` is
empty. If it isn't, stop and fix the toolchain first — otherwise your
real change will be buried in thousands of lines of incidental churn.

Note that `bison -d -o foo.C` writes the header as `foo.H` (it maps the
output extension's case), which is what the repo tracks. On macOS's
case-insensitive APFS `foo.h` and `foo.H` are the same file; on Linux
they are not, but bison produces `.H` on both, so this is consistent.

## Running ds9 / smoke-testing over XPA

`xpans` (the XPA name server) must be on the `PATH` **before** ds9
launches, or ds9 starts fine but never registers and every `xpaget`/
`xpaset` fails. The tools live in `bin/` alongside `ds9`:

```
PATH="$PWD/bin:$PATH" ./bin/ds9 &
```

Then confirm registration before sending anything (it takes ~1s):

```
./bin/xpaaccess ds9
```

To reach C++ frame commands that have no Tcl/menu plumbing yet, use the
`tcl` XPA entry point, which does `uplevel #0` on whatever it receives
(local connections only). This is the fastest way to exercise a new
grammar rule in isolation:

```
echo '$::current(frame) reveal 400' | ./bin/xpaset ds9 tcl
```

### A crashed or killed ds9 leaves a trap for the next one

On a clean exit ds9 deletes its auto-recovery files; when it crashes or
is killed (lldb, `timeout`, stopping the shell that started it) it
can't. The next instance **with the same `-title`** finds them and opens
a modal "Found Auto Backup, restore?" dialog (`AutoSaveRestore`,
`autosave.tcl`) that blocks it, even with `autosave 0` in the prefs.
The files are `~/<title>.auto` and `~/<title>.auto.dir`, so clear them
before relaunching:

```
rm -rf ~/DS9Test.auto ~/DS9Test.auto.dir
```

Use a distinct `-title` per test run, and don't leave a background
script running against a title you reuse: its final `exit` will close
the next instance. A ds9 that stops answering is usually a modal dialog,
not a hang; `sample <pid> 2` showing `-[NSAlert runModal]` confirms it.

Shut ds9 down with `./bin/xpaset -p ds9 exit` rather than killing the
process — that is the supported way and it exits cleanly. (`pkill` also
tends to miss the `./bin/ds9` wrapper and leave a stray process that
holds the XPA name, so the next launch registers a second instance and
`xpaget` answers from both.)

Errors surface as `XPA$ERROR ...` on the `xpaset` call. To capture
richer results, have the sent Tcl write to a file rather than trying to
read a return value. Useful handles: `$::current(frame)` is the frame's
canvas-item command (e.g. `Frame1` — a canvas item, *not* a window, so
`winfo` does not work on it); its on-screen size comes from
`$::ds9(canvas) itemcget $::current(frame) -width`. For visual checks,
`./bin/xpaset -p ds9 saveimage png /path/out.png` captures the canvas,
and comparing sha256 of before/after captures makes render changes and
clean round-trips objectively verifiable. Shut down with
`./bin/xpaset -p ds9 exit`.

## Regression test scripts (`Tests/`)

`Tests/` is a separate git repo, untracked here. Keep it out of commits
to this repo. Its scripts call bare `ds9`, `xpaaccess` and GNU
`timeout`. macOS has no `timeout`; a replacement script is in
`$HOME/local/bin`. The scripts use paths relative to `Tests/` (e.g.
`fits/...`), so run them from inside `Tests/`, with the built `bin/` and
`$HOME/local/bin` on the `PATH`. That also puts `xpans` there before ds9
starts:

```
cd Tests && PATH="$PWD/../bin:$HOME/local/bin:$PATH" ./moc.sh
```

Until 2026-10-14 the `timeout` replacement waited the *full* duration
when its output went to `$(...)` or a pipe (its timer's `sleep` kept the
pipe open), which made every wrapped XPA call look slow. It now
redirects the timer's output; if timings look padded to the timeout
value, check that the fix is still in place.

Some scripts call other scripts by bare name (e.g. `nrrd.sh` runs
`full.sh`), so for those put `Tests/` itself on the `PATH` too:
`PATH="$PWD:$PWD/../bin:$HOME/local/bin:$PATH"`.
